# Savvo Android Deploy Runbook (internal testing to Google Play)

This is the end-to-end runbook to take Savvo from this repo to an Android App
Bundle (AAB) on the Play Console internal testing track and then to production.
It mirrors `ios/DEPLOY-IOS.md`.

Key facts (do not let these drift):

- **appId / applicationId / namespace:** `app.savvo` (`capacitor.config.ts`,
  `android/app/build.gradle`). Once an app is published on Play, the package
  name can never change.
- **appName:** `Savvo`
- **Model:** `server.url` -> the native WebView loads the live site at
  `https://savvo.app`. The app is a thin native shell with native plugins
  (push, share, status bar, haptics, browser, in-app purchases) layered on top.
  `cleartext: false` keeps it HTTPS only.
- **versionName:** `0.1.0` (matches `package.json`), **versionCode:** `1`
  (`android/app/build.gradle`).
- **SDK levels** (`android/variables.gradle`, from the Capacitor 8 template):
  `minSdkVersion 24`, `compileSdkVersion 36`, `targetSdkVersion 36`.

Run all commands from the repo root.

---

## 0. Prerequisites (one time)

1. **Android Studio** (latest stable). It bundles a JDK 21 runtime that the
   Capacitor 8 Gradle setup expects. In Android Studio -> Settings -> Languages
   & Frameworks -> Android SDK, install:
   - Android SDK Platform 36
   - Android SDK Build-Tools (latest)
   - Android SDK Command-line Tools
   - An emulator image (for example a Pixel with Android 15 or 16)
2. Export the SDK location so the Capacitor CLI and Gradle can find it (add to
   `~/.zshrc`):

   ```bash
   export ANDROID_HOME="$HOME/Library/Android/sdk"
   export PATH="$ANDROID_HOME/platform-tools:$ANDROID_HOME/cmdline-tools/latest/bin:$PATH"
   ```

   Or create `android/local.properties` with `sdk.dir=/Users/<you>/Library/Android/sdk`
   (that file is gitignored).
3. **Google Play Console developer account** (one-time $25 fee) at
   https://play.google.com/console. New personal accounts must run a closed
   test with at least 12 testers for 14 days before they can apply for
   production access. Organization accounts (with a D-U-N-S number) skip that
   requirement, so decide which account type to create before you start.
4. `npm ci` so `node_modules/@capacitor/*` exists (the Gradle project links
   plugins straight from `node_modules`).

## 1. The native project

`android/` is committed (generated by `npx cap add android`). Build outputs,
`local.properties`, keystores, and `google-services.json` are gitignored by
`android/.gitignore`.

What we customised on top of the template:

- `AndroidManifest.xml`
  - `app.savvo://auth/callback` intent filter for native Google sign-in
    (`src/lib/native/google-auth.ts`).
  - `android:autoVerify="true"` App Links filter for `https://savvo.app/auth/*`
    (Supabase email verify and password reset return into the app), mirroring
    the iOS `apple-app-site-association` components.
  - `POST_NOTIFICATIONS` (Android 13+ push permission prompt).
  - `CAMERA` with `android.hardware.camera` `required="false"` so the `/scan`
    LinkedIn QR scanner can use `getUserMedia` inside the WebView.
- Launcher icon (adaptive + legacy), round icon, and splash rendered from
  `public/icon.svg` in the copper brand color; Android 12+ splash background is
  sand `#FAF9F7`.

---

## 2. Sync and open

Run after `npm ci`, after **every** Capacitor plugin add/upgrade, and after any
change to `capacitor.config.ts`:

```bash
npm run android:sync   # cap sync android
npm run android:open   # cap open android (opens Android Studio)
```

Let Gradle sync finish in Android Studio before building.

To point a build at staging instead of production, set
`CAPACITOR_SERVER_URL=https://<preview-host>` when you run `android:sync`
(it is read at sync time and baked into `capacitor.config.json`). Always sync
again without it before a release build.

---

## 3. Firebase / FCM (`google-services.json`) for push

Android push goes through Firebase Cloud Messaging. `@capacitor/push-notifications`
needs a `google-services.json`. **It is per-project config and is never
committed** (gitignored).

1. https://console.firebase.google.com -> Add project (for example `savvo-prod`).
   Google Analytics for Firebase is not needed; leave it off unless you want it,
   because it changes the Data safety answers.
2. Project settings -> General -> Your apps -> Add app -> Android.
   - Package name: `app.savvo`
   - SHA-1: optional for FCM (needed only for Firebase Auth features).
3. Download `google-services.json` and place it at
   `android/app/google-services.json`.
4. Project settings -> Cloud Messaging: make sure the **Firebase Cloud
   Messaging API (V1)** is enabled. Create a service account key (Project
   settings -> Service accounts -> Generate new private key) for whatever
   backend sends pushes. Store it as a server secret, never in the repo.

Without the file the build still succeeds: `android/app/build.gradle` wraps
`apply plugin: 'com.google.gms.google-services'` in a try/catch and only logs
"google-services.json not found ... Push Notifications won't work". So debug
builds work for everything except push. Do not ship a release without it if
push is part of the release.

Note: the device token registration in `src/lib/native/capacitor.ts` is owned
by the push notifications work. When it posts the token, it must send
`platform: "android"` on Android (FCM token) and `"ios"` on iOS (APNs token),
because the sender uses different credentials for each.

## 4. Upload key and Play App Signing

Play App Signing is mandatory for new apps. Google holds the **app signing
key**; you sign uploads with an **upload key** you control.

1. Generate the upload keystore once and store it in your password manager
   (losing it means a support request to reset):

   ```bash
   keytool -genkeypair -v \
     -keystore ~/keys/savvo-upload.jks \
     -alias savvo-upload \
     -keyalg RSA -keysize 4096 -validity 10000
   ```

   Keep it outside the repo. `*.jks` and `*.keystore` are gitignored anyway.
2. In Android Studio: Build -> Generate Signed App Bundle or APK -> Android App
   Bundle -> choose the keystore and alias -> `release` build variant. Android
   Studio can remember the passwords locally. Alternatively, create
   `~/.gradle/gradle.properties` entries and a `signingConfigs` block; do not
   commit passwords.
3. On the first upload, Play Console offers Play App Signing; accept "Use
   Google-generated key" (recommended).

---

## 5. Version numbers

Before every upload, bump in `android/app/build.gradle`:

- `versionCode`: an integer that **must increase for every upload**, on any
  track. Play rejects a reused versionCode.
- `versionName`: the user-visible version. Keep it in step with
  `package.json` (`0.1.0` today) and the iOS marketing version.

---

## 6. Build the AAB

Android Studio: Build -> Generate Signed App Bundle (step 4), or from the CLI
once signing is configured:

```bash
npm run android:sync
cd android
./gradlew bundleRelease
# Output: android/app/build/outputs/bundle/release/app-release.aab
```

A quick unsigned debug APK for an emulator or a USB device:

```bash
cd android && ./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## 7. Create the app in Play Console

1. Play Console -> Create app.
   - App name: `Savvo: Relationship Manager` (see `PLAY-STORE-METADATA.md`)
   - Default language: English (United States)
   - App or game: App. Free or paid: Free (Pro is an in-app subscription).
   - Accept the declarations.
2. Dashboard -> "Set up your app" tasks. Use `android/PLAY-STORE-METADATA.md`
   for every answer: privacy policy URL, app access (demo account), ads (No),
   content rating, target audience, news app (No), data safety, government app
   (No), financial features (No), health (No).
3. Main store listing: title, short and full description, icon
   (`store-assets/android/play-icon-512.png`), feature graphic
   (`store-assets/android/feature-graphic-1024x500.png`), phone screenshots
   (`store-assets/android/phone-*.png`), 7-inch and 10-inch tablet screenshots
   optional (`store-assets/ios/ipad-*.png` crops are not the right ratio; take
   dedicated ones if you add tablet support to the listing).

## 8. Internal testing track

1. Testing -> Internal testing -> Create new release.
2. Upload `app-release.aab`. On the first upload, confirm Play App Signing.
3. Release name: `0.1.0 (1)`. Release notes: short and plain.
4. Testers tab: create an email list (up to 100 testers), save, and copy the
   opt-in link. Testers join through the link, then install from Play.
5. Internal testing has no review delay and is the fastest loop. Use it for
   every build first.

Real device smoke test (both light and dark mode):

- App opens to `https://savvo.app`, sign in with email works.
- Continue with Google: the system browser (Custom Tab) opens, consent, and
  you return to the app signed in (proves the `app.savvo://auth/callback`
  intent filter and the Supabase allowlist).
- Tap a password reset email link on the device: it opens in the app, not
  Chrome (proves App Links verification, step 9).
- Push permission prompt appears once push registration ships (Android 13+).
- `/scan` asks for camera permission and scans a LinkedIn QR code.
- Pro upgrade shows the Google Play purchase sheet (step 10).
- Status bar and gesture bar do not overlap content. Capacitor 8 injects
  `--safe-area-inset-*` CSS variables on Android; confirm the sticky header and
  the floating add button clear the system bars.
- The system back gesture navigates back inside the WebView.

## 9. App Links: `assetlinks.json` fingerprint

`https://savvo.app/.well-known/assetlinks.json` (source:
`public/.well-known/assetlinks.json`) tells Android that `app.savvo` may open
`https://savvo.app/auth/*` links. It ships with the placeholder
`REPLACE_WITH_PLAY_APP_SIGNING_SHA256_FINGERPRINT`.

1. Play Console -> your app -> Test and release -> Setup -> **App signing**
   (App integrity -> App signing in some layouts).
2. Under **App signing key certificate**, copy the **SHA-256 certificate
   fingerprint** (format `AB:CD:...`, 32 colon-separated byte pairs).
   Use the app signing key, not the upload key: the installed app is
   re-signed by Google with the app signing key.
3. Replace the placeholder in `public/.well-known/assetlinks.json` with that
   value. To also verify debug or sideloaded upload-key builds, add the upload
   key's SHA-256 as a second entry in `sha256_cert_fingerprints`
   (`keytool -list -v -keystore ~/keys/savvo-upload.jks -alias savvo-upload`).
   `src/__tests__/android-app-links.test.ts` currently expects exactly one
   fingerprint; relax that assertion if you add a second.
4. Deploy the web app. Confirm:

   ```bash
   curl -sI https://savvo.app/.well-known/assetlinks.json   # 200, content-type: application/json, no redirect
   ```

   Then validate with Google's tester:
   https://developers.google.com/digital-asset-links/tools/generator
   (site `savvo.app`, package `app.savvo`, the fingerprint).
5. On a device after install: `adb shell pm get-app-links app.savvo` should
   show `savvo.app: verified`. To force re-verification:
   `adb shell pm verify-app-links --re-verify app.savvo`.

The file is served by Next.js from `public/` with `Content-Type:
application/json` (inferred from the `.json` extension); `src/proxy.ts` does
not redirect `/.well-known/*`, so no extra header rule is needed.

## 10. Google Play Billing via RevenueCat

Google Play's Payments policy requires Play Billing for digital subscriptions
bought inside the app. The code path is already in place:
`src/lib/native/purchases.ts` picks the RevenueCat key by
`Capacitor.getPlatform()` (Android uses `NEXT_PUBLIC_REVENUECAT_ANDROID_KEY`,
iOS uses `NEXT_PUBLIC_REVENUECAT_IOS_KEY`). If the Android key is missing the
upgrade fails closed with "Purchases are not configured"; it never falls back
to Stripe or to the iOS key. Stripe stays web only.

1. **Products in Play Console.** The app must have at least one AAB uploaded
   (internal track is enough) before you can create subscriptions. Then
   Monetize -> Products -> Subscriptions -> Create:
   - `savvo_pro` subscription with two base plans: `monthly` (auto-renewing,
     1 month) and `annual` (auto-renewing, 1 year). Match the web prices shown
     on `/pricing`.
2. **Service account for RevenueCat** (lets RevenueCat validate purchases and
   receive Real-time developer notifications):
   - Google Cloud Console (the project linked to Play Console) -> enable the
     **Google Play Android Developer API** and **Google Cloud Pub/Sub API**.
   - IAM -> Service accounts -> create `revenuecat-play`, then create a JSON key.
   - Play Console -> Users and permissions -> Invite new user -> the service
     account email. Grant app permissions: View app information and download
     bulk reports, View financial data, Manage orders and subscriptions.
   - It can take up to 36 hours for the credentials to become valid.
3. **RevenueCat dashboard.**
   - Project -> Apps -> + New -> Google Play Store. Package `app.savvo`.
     Upload the service account JSON.
   - Enable **Google Real-Time Developer Notifications** (RevenueCat creates
     the Pub/Sub topic; paste the topic into Play Console -> Monetization
     setup).
   - Products: import `savvo_pro:monthly` and `savvo_pro:annual`. Attach both
     to the existing entitlement **`pro`**.
   - Offering: add the Play products to the **current** offering's `$rc_monthly`
     (MONTHLY) and `$rc_annual` (ANNUAL) packages next to the App Store ones.
   - Copy the **public Google Play SDK key** (starts with `goog_`).
4. **Env vars** (Vercel, every environment you build native from, then
   redeploy because `NEXT_PUBLIC_*` is inlined at build time):
   - `NEXT_PUBLIC_REVENUECAT_ANDROID_KEY` = the `goog_` key.
   - `REVENUECAT_WEBHOOK_AUTH` and `REVENUECAT_ATTRIBUTE_SECRET`: already used
     for iOS; one webhook serves both stores. `REVENUECAT_ATTRIBUTE_SECRET` is
     a launch gate: without it the webhook refuses to grant Pro in production.
5. **Webhook.** The existing RevenueCat webhook
   (`https://savvo.app/api/native/revenuecat-webhook`) receives Play events
   with `store: "PLAY_STORE"` and handles them exactly like App Store events
   (covered by `src/__tests__/integration/api-revenuecat-webhook.test.ts`).
6. **License testing.** Play Console -> Settings -> License testing: add your
   tester Gmail accounts. Their purchases on the internal track are free test
   purchases with accelerated renewals.
7. Smoke test: Upgrade on `/pricing` -> Play purchase sheet -> `pro`
   entitlement active -> RevenueCat webhook flips `subscriptions.plan` to
   `pro` -> dashboard shows Pro. Cancel in the Play Store app; after expiry the
   webhook downgrades.

Users manage or cancel the subscription in the Play Store app (Payments and
subscriptions). A Stripe customer portal link must not be shown to a Play
subscriber.

## 11. Supabase Auth redirect allowlist

Supabase -> Authentication -> URL Configuration -> Redirect URLs. Make sure
these are present (the first is shared with iOS):

- `app.savvo://auth/callback` (native Google sign-in on iOS and Android)
- `https://savvo.app/auth/callback` (email verify and reset; App Links route
  it into the app once `assetlinks.json` verifies)

No separate Android OAuth client is needed: Google sign-in runs through the
existing Supabase Google provider in the system browser.

---

## server.url model on Android

- A web deploy updates the app's content instantly; only native changes
  (plugins, permissions, `capacitor.config.ts`, icons, version) need a new AAB.
- Never break `https://savvo.app`; it is the app.
- Google Play's "Minimum functionality" and "Webviews" policies reject apps
  that are only a website wrapper. Lead with the native value in the listing
  and reviewer notes: push notifications for "going cold" and digest nudges,
  native share sheet, Play Billing, Google sign-in via the system browser,
  App Links, haptics, camera QR scanning.
